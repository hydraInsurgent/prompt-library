# Library Sync and Project Registry

**Overall Progress:** `12.5%` (Step 0 done; awaiting review before Step 1)

## TLDR

Sync the prompt library with consumer projects and add a `projects/` folder = consumer registry. Library becomes the canonical source for shared workflow commands; each consumer project gets a snapshot in `projects/<name>/` (description, manifest, CLAUDE.md, toolkit.md, overrides). Drift becomes visible without filesystem scans. Sets up the foundation for a future `plib sync` CLI (separate issue).

- `registry.json` auto-generated by `plib build-registry`. Manual version sync deviation closed.
- 3 new CLI subcommands: `plib snapshot <path>`, `plib detect-drift <path>`, `plib build-registry`.
- New `docs-workflow` package houses `/document`, `/guides`, `/learnings`. `core-workflow` → 2.0.0 (loses `/document`).
- New `patternarium` and `dotnetarium` packages extracted from their respective projects; name collisions resolved.
- Daily-builds `lab-` prefix policy enforced library-wide.
- Every formal consumer has a `.plib-lock.json` and a snapshot in `projects/<name>/`. Friend's `Resume` snapshot exists but is marked `external: read-only`.
- Documentation updated: `architecture.md`, `product-design.md`, `engineering-guidelines.md`, `PACKAGE-SPEC.md` all reflect the new structure.

## Critical Decisions

- **Two-tier registry** - formal consumers receive `plib install` updates and have lock files; external/read-only projects (friend's repos) get snapshots without installs. Manifest field `external: true` distinguishes them.
- **Unique command names library-wide** - every command file's basename must be unique across all packages. Folder-scoped names (`lab/concept.md`) are technically possible but Claude Code surfaces them awkwardly, so deferred. Known collisions to resolve in this work: Dotnetarium `explore.md`, Patternarium `review.md`.
- **Naming convention for `projects/<name>/`** - `Depth Projects/` keeps plain names (canonical); same-named projects elsewhere use parent-context prefix (`cursor-tasklog`, `old-tasklog`).
- **`core-workflow` 2.0.0 is breaking** - removes `/document`, which moves to new `docs-workflow@1.0.0`. Existing consumers (phonectl, Threadpuller, workbench) reinstall to add docs-workflow. Justified by long-term clarity over migration cost.
- **`registry.json` becomes an auto-generated artifact** - new `plib build-registry` subcommand reads `packages/*/plib.json` and writes the registry. Closes the "Manual version sync" deviation in `engineering-guidelines.md`.
- **Cleanup is strict report -> prompt -> act per item** - project data is never archived/deleted automatically. Every candidate gets surfaced; user confirms each one before any folder move or delete. Captured in saved feedback memory.
- **Single ship at the end** - many commits along the way, one PR, one version tag. Easier to reason about as a single coherent change.
- **Test discipline** - one throwaway test directory used throughout; every package install verified there before moving on.
